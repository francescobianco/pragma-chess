# Opening names

Two opening names databases are shipped and seeded into the user's
`Books/Opening Names` folder on first launch, ready made so that the first
launch is not spent building them. Each game in them is a named line: Event is
the name, ECO the code, and the name belongs to the position where the line
ends. Both are version 5 `.pdb` files of type `opening-book` with a fixed
lineage id (see `app/GameIdentity.h`), so every install and update is the same
database, and a display name in several languages (`name`, `name.it`), which
Options ▸ Opening Names shows instead of the file name.

| File | Seeded as | Names | Lineage | Built from |
|------|-----------|-------|---------|------------|
| `opening-names.pdb` | `English.pdb` | English / Inglese | `…4c01` | `lichess-openings.tsv` |
| `opening-names-it.pdb` | `Italian.pdb` | Italian / Italiano | `…4c03` | `lichess-openings-it.tsv` |

`lichess-openings.tsv` is the named openings of
[lichess-org/chess-openings](https://github.com/lichess-org/chess-openings), a
public domain (CC0) collection. `lichess-openings-it.tsv` has the same ECO codes
and moves with the names in Italian, as Italian chess books write them
("Difesa Siciliana: Variante Najdorf", "Partita Spagnola: Chiusa",
"Gambetto di Donna Rifiutato: Variante di Cambio"). It is generated by
`make-italian-names.py`: a hand-written dictionary (every opening family, the
kinds of line with their gender, adjectives, common nouns, places) plus word
order rules; words not in it are proper names and are kept. Improve a name by
extending the dictionary (or `PHRASES` for whole parts), never by editing the
TSV by hand:

```bash
cd gui/qt/resources/openings
python3 make-italian-names.py            # rewrites lichess-openings-it.tsv
python3 make-italian-names.py --unknown  # capitalized words kept as they are
```

The TSVs are shipped too: the app builds a database from its TSV if the ready
made one cannot be copied.

To rebuild the `.pdb` files after changing a TSV, build a database from each
TSV with `OpeningNames::gamesFromTsv` and `SqliteGameDatabase::create`, then set
its properties (id, `type = opening-book`, a description, `name` and
`name.it` as in the table; `ShippedOpeningNames` has them) — a few lines of C++
linked with the app's objects. Or let the fallback do it: take the two `.pdb`
files out of `qt_add_resources(... openings ...)` in `gui/qt/CMakeLists.txt`,
build, and run once on a scratch folder:

```bash
rm -rf /tmp/pragma-seed
PRAGMA_CHESS_DIR=/tmp/pragma-seed ./build/gui/qt/pragma-chess   # quit once it opens
cp "/tmp/pragma-seed/Pragma/Books/Opening Names/English.pdb" gui/qt/resources/openings/opening-names.pdb
cp "/tmp/pragma-seed/Pragma/Books/Opening Names/Italian.pdb" gui/qt/resources/openings/opening-names-it.pdb
```

then put them back in the resources and build again.
